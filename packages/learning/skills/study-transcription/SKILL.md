# 录音转写

已有讲稿、课堂文字记录或转写稿时直接读取，不安装、不启动转写工具。不凭文件名猜测已有资料是否就是本次录音的原稿；有疑问读取内容，必要时简短询问。录音不是每节课的必需输入。

用户需要识别录音时，先 `study_desktop read` 读取实际文件身份、版本与来源，再 `study_transcribe status` 查看当前安装和任务状态。说明音频在运行软件的电脑处理；转写结果交给助理后，所需文字可能按普通提问发送到模型服务。

## 首次启用

先用 `check` 检查用户电脑的实际加速方式、可用内存、显存和磁盘。默认使用 Apple Silicon 的 Metal 或 Windows/Linux 的受支持 NVIDIA GPU，不默认使用 CPU，也不在 GPU 失败后悄悄退回 CPU。资源未知或不足时禁止下载。

桌面应用负责启动和关闭转写服务，用户不需要运行命令或安装另一个界面。连接失败时建议重新打开应用，再检查；仍不可用时保留录音，说明这次无法转写，已有文字稿仍可直接使用。没有受支持 GPU 时说明限制，不要求用户下载无法使用的推理组件，也不将 CPU 模式作为默认替代。

`start` 返回 `needs_install` 时说明检测选定的后端、返回的内存/显存/磁盘要求，以及首次需下载运行环境和约 3.8 GiB 模型。用户明确同意后才传 `allow_install=true`，不因上传音频自动下载。已有文字稿则完全无需这些步骤。

有其他转写正在处理时等待或按用户要求停止，不并发加载多份模型。下载失败或资源不足时说明具体阶段，保留原录音、已下载内容和断点，不将失败说成完成。

## 调用与恢复

`study_transcribe start` 输入真实 `file` 和当前哈希 `expected`，启动或接续后台任务。返回后及时说明正在处理，让用户可以继续其他工作；不循环调用工具等到完成。需要查看时用 `status`，用户要求停止时用 `stop(job)`。

任务完成后读回实际保存的文本文件，核对来源仍对应那份录音；未完成、识别为空或版本冲突时不制造文稿。原稿保存在原录音的课程文件夹，关联来源，原录音保留。中断后继续同一录音版本，复用已完成片段，不覆盖已保存的原稿。

## 原稿与后续整理

自动识别可能听错专业术语、数字、公式或人名。没有可核对的证据时保留不确定，不凭常识补全为课堂事实，不声称逐字准确。用户指出错误时保留原稿，再保存有依据的修订。

转写只生成文字原稿，不自动生成笔记、布置练习、登记授课终点或认定用户已学习。用户需要进一步整理时，结合实际课件与要求，按课程材料或笔记规范处理。选择不转写不阻碍其他学习操作。
